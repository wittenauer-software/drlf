# Contributing to DRLF

DRLF welcomes generalized software, documentation, public foundations, and unmistakably synthetic
tests. It does not accept identifiable investigations, allegations, candidate lists, PHI, beneficiary
data, real NPIs, retained source data, or fraud tips.

## Before opening a contribution

- Start from current public `main` on a short-lived branch with no private repository history.
- Keep real research in an independent private workspace; reimplement any general improvement from
  public authority, formal reasoning, and synthetic evidence without private lineage or values.
- Register every identity-like fixture in `examples/synthetic-identities.yaml`.
- Update code, tests, catalogs, and documentation together. Do not add hosted automation, telemetry,
  automated security configuration, or external services without a maintainer-approved design.
- For a skill change, obtain explicit maintainer permission for the proposed target, rationale,
  behavior, files, and validation before editing skill files.

## Local validation

Use the supported Windows setup and run the documented Ruff, test, schema/catalog, migration,
synthetic-workflow, link, and whitespace checks. Inspect the complete diff and dependency/license
impact. State validation and documentation impact in the pull request.

Contributor code and branches are untrusted until reviewed. Maintainers may inspect a contribution in
a disposable credential-free checkout before running it. A passing check does not guarantee merge.
