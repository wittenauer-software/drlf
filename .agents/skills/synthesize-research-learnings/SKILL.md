# Synthesize research learnings

Preserve what worked, failed, weakened a hypothesis, or exposed a data limit without turning a prior
case into unsupported general truth.

Use [the local-learning schema](references/learning-schema.md), start new records from
`assets/learning-card.md`, and run `scripts/validate_knowledge.py` before treating the index as valid.

## Select the memory layer

- `foundations/catalog.yaml` is the read-only public baseline. Resolve records by semantic title,
  type, and full scope; never renumber or edit it during case research.
- A verified private workspace stores case-derived local learning in its separate local namespace.
- The public checkout may run only the declared synthetic learning exercise and may write only to its
  disposable output location.

## Synthesize and reconcile

1. Work from case evidence, source records, decisions, artifacts, cutoff review, and retrospective,
   not chat history alone.
2. State program, dataset, year, code, population, geography, operational setting, confidence, and
   invalidation conditions. Preserve counterevidence and failed approaches.
3. Search both indexes for overlap or contradiction. Create a new local identifier only when the
   lesson is distinct; supersede or reject a contradicted record without deleting history.
4. Keep candidate, reviewed, adopted, experimental, superseded, and rejected status meanings
   explicit. A learning guides later method selection but is never evidence for another case.
5. Run the local-learning validator and rebuild the combined index while retaining identifier,
   origin, version, scope, confidence, and evidence rules.

## Propose durable changes

Promote a reusable behavior only when it recurs independently, is established by an authoritative
source, or prevents a material research error. A private lesson may motivate a public improvement,
but the public rationale must be newly supported with public authority, formal reasoning, and
registered synthetic tests; private identity, values, IDs, hashes, and narrative lineage stay private.

Proactively notice a warranted skill improvement. Before editing a skill, ask the user for explicit
permission and state the target, evidence/value, behavior and boundaries, affected files, and
validation. Stop if permission is absent. General upgrade or research permission is not enough.
