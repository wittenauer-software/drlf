# Security policy

## Supported version

Security fixes are provided for the latest v0.1 repository state until a later support policy is
published.

## Reporting

Sensitive intake is closed for v0.1. DRLF currently offers no verified confidential maintainer
reporting channel. Do not submit vulnerability details, exploit examples, credentials, private
workspace contents, PHI, beneficiary data, or identifiable healthcare allegations in public issues,
pull requests, discussions, or other project surfaces. Do not send them to an inferred personal address.

A maintainer may enable a confidential channel in a later reviewed policy update after verifying
its access controls and successful private receipt. Until that update identifies a tested route,
retain sensitive details privately. Ordinary non-sensitive software bugs may use the documented
support process, with synthetic reproductions only.

This policy does not authorize access to systems, data, accounts, or records that you do not own or
have permission to test. It does not offer an incident-response service or a response-time guarantee.

Identifiable healthcare research material is not a software vulnerability report. Do not send it to
this project through any channel.
